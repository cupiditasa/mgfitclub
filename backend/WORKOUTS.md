# برنامه‌های تمرینی و غذایی — وضعیت تغییرات محلی ۲۰۲۶-۱۰-۰۵

قابلیت برنامه تمرینی فعال است. در ۲۰۲۶-۱۰-۰۵ مهاجرت غذایی روی D1 و Worker جدید منتشر شد؛ صفحات غذایی هنوز باید روی GitHub Pages منتشر شوند. از D1 و Worker نسخه پشتیبان خصوصی گرفته شده است. ورود، پیامک و تردد تغییر نکرده‌اند.

## انتشار بعد از تأیید

1. نسخه پشتیبان پیش از انتشار تهیه شده است؛ فایل‌های آن خصوصی‌اند و نباید وارد Git شوند.
2. مهاجرت افزایشی `migrations/010-nutrition-plans.sql` روی D1 اعمال شده و جداول/ایندکس‌ها/triggerها و foreign keyها بررسی شده‌اند.
3. Worker با ماژول‌های **workouts.js، nutrition.js و workout-domain.js** منتشر شده و bindingهای قبلی حفظ شده‌اند.
4. مرحله باقی‌مانده، انتشار صفحات فرانت‌اند و service worker روی GitHub Pages است؛ فقط آپلود HTML کافی نیست.
5. پس از انتشار، با حساب‌های واقعی مربی/ورزشکار و مدیر، ذخیره، ارسال، دریافت و گزارش را بررسی کنید. برای ارسال، مربی باید club_id تأییدشده داشته باشد.

بازگشت امن: feature flag را غیرفعال کنید؛ جداول یا نسخه‌های ارسالی را حذف نکنید. در صورت لزوم فایل‌های فرانت‌اند قبلی را برگردانید.

## قواعد داده

- ۱۵۵ نام از فایل ارائه‌شده وارد شده‌اند؛ متن‌های راهنمای ورزشی و رسانه‌های نمونه وارد نشده‌اند.
- ۱۵ گروه بدنی (شامل گروه‌های کلی منبع و گزینه‌های جزئی‌تر) و ۴ سبک جداگانه. گروه‌بندی علمی خودکار انجام نشده است.
- نام یکتا با NFKC، یکسان‌سازی ی/ک، ارقام و حذف فاصله/علائم؛ نام‌های مترادف با واژه‌های متفاوت نیاز به بازبینی انسانی دارند.
- ۷ روز و حداکثر ۲۰ حرکت در هر روز. ست ۱–۵۰، تکرار ۱–۱۰۰۰، مدت هر ست ۱–۳۶۰۰ ثانیه و استراحت ۰–۳۶۰۰.
- زمان = مجموع (ست × مدت اجرا + (ست − ۱) × استراحت بین ست‌ها) + استراحت بین حرکات، بدون استراحت بعد از حرکت آخر.
- هر ارسال یک snapshot مستقل و غیرقابل تغییر است؛ ویرایش قالب فقط نسخه‌های آینده را عوض می‌کند.
- دریافت‌کننده فاقد باشگاه قابل انتخاب است؛ دریافت‌کننده با باشگاه متفاوت رد می‌شود. باشگاه گزارش از عضویت مربی در سرور تعیین می‌شود.
- افزودن ویدیو فعلاً API ثبت metadata برای فایل‌های HTTPS همان دامنه است، نه آپلود فایل. صفحه نهایی آموزش/بارگذاری ویدیو پس از دریافت طرح کاربر تکمیل می‌شود.
- این نسخه آنلاین است؛ کش service worker جای دیتابیس یا مجوز آفلاین را نمی‌گیرد. تایمر در همان صفحه با ساعت monotonic کار می‌کند؛ reload تایمر را از نو شروع می‌کند.

## برنامه غذایی — D1 و Worker فعال، صفحات در انتظار انتشار

برنامه غذایی ساختار جدا دارد: هفت روز، تا ۲۰ وعده در هر روز، نوع وعده و توضیحات متنی. عنوان‌ها و نمادهای نمایش برای صبحانه، ناهار، شام، میان‌وعده، مکمل، قبل خواب، بعد از خواب، قبل تمرین، بعد تمرین و حین تمرین در رابط هستند. روز ورزشکار بر اساس ساعت تهران انتخاب می‌شود. ارسال‌ها نسخه مستقل دارند و در همان گزارش باشگاه با برچسب «برنامه غذایی» دیده می‌شوند.

مهاجرت افزایشی `migrations/010-nutrition-plans.sql` روی D1 اعمال و Worker همراه `nutrition.js` منتشر شده است. endpoint گزارش یکپارچه اکنون جدول‌های برنامه تمرینی و غذایی را می‌خواند؛ صفحات فرانت‌اند پس از انتشار به آن وصل می‌شوند.

## مسیرهای API

همه زیر /api/workouts و نیازمند ورود و حساب تأییدشده‌اند:

- GET catalog / POST exercises
- GET و POST exercises/:id/videos
- GET و POST templates
- GET و PATCH templates/:id
- POST templates/:id/send و templates/:id/archive
- GET deliveries و deliveries/:id

تغذیه در /api/workouts/nutrition: GET types, GET/POST templates, GET/PATCH templates/:id, POST templates/:id/send و /archive، GET deliveries.

POST ساخت و ارسال نیازمند requestKey یکتا هستند؛ PATCH و ارسال نیازمند revision فعلی‌اند.
