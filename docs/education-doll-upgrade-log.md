# دفتر ارتقای مدل عروسکی MG

## Cross-cutting load and anatomy repair (outside the 30 doll-design stages)

- Root cause confirmed locally: the optional medical GLB has 17 meshes and about 1,109,054 triangles. The GLB is valid and Meshopt-decodes successfully, but this geometry is expensive to fetch, decode, and render on mobile.
- Fix: preserve the original source GLB; create a separately named web derivative in Blender 5.2.2 at a 0.32 Decimate ratio, retaining all 17 mesh objects, then Meshopt-compress it. Node/Three GLTFLoader parse verification reports about 354,877 triangles and 3,788,704 bytes (about 30% smaller than the 5,408,156-byte source).
- Startup fix: create the Three.js doll only after the learning workspace is selected/idle; the planner no longer constructs the doll or runs a perpetual animation loop. The draw loop also pauses when the tab is hidden or the planner is active.
- Anatomy stays optional, and the doll remains the default. The anatomy request is versioned to avoid a stale service-worker asset and reports transfer progress. Manual local Chrome verification on 2026-10-13: the doll rendered first; requesting anatomy rendered the medical model; selecting the chest hotspot opened its region panel with four related exercises; changing back to the doll rendered the animated training model again. No browser console errors or warnings were reported. This verifies local rendering and switching, not a precise network/GPU timing benchmark.
- Automated validation: full backend suite passes (245/245); anatomy parsing test confirms all 17 selectable meshes and 354,877 triangles; `git diff --check` is clean. Local Meshopt parse median was 46 ms for the original and 24 ms for the web derivative across three runs (measurement is local Node parsing, not browser/GPU timing).
- Remote publication is not included. Chrome access has now been restored and the local working-tree preview was inspected successfully. The local build is still unpublished. The current front/side and biceps-curl views sign off only the scoped checks recorded here; the remaining geometry stages still need their own targeted angle and pose reviews.
- Read-only live audit on 2026-10-13: `education-studio.html` still references `mg-male-anatomy.glb`; that source returns HTTP 200 at 5,408,156 bytes, while `mg-male-anatomy-web-v1.glb` currently returns HTTP 404. The live service worker is still `mg-fitclub-v20261013-tailored-garments-v1`, not this worktree's v8. This confirms the local optimization has not reached the live site; production cannot be called fixed until the matching HTML, GLB, and service worker are deployed together and visually checked.

## یادداشت اجرای مراحل

### مرحلهٔ ۱ — ۲۰۲۶-۱۰-۱۳

### مرحلهٔ ۲ — ۲۰۲۶-۱۰-۱۳؛ بازبینی تصویری در انتظار

- تغییر هدف: کم‌کردن درخشش مصنوعی لباس و واضح‌ترکردن بافت پارچه.
- تغییر کد: بافت داخلی پارچه از ۶۴×۶۴ به ۱۲۸×۱۲۸، افزایش تفکیک بافت، پارچه با roughness برابر ۰٫۹۸ و حذف clearcoat پارچه.
- آزمون: تست‌های هدفمند عروسک/استودیو و کل پروژه (۲۳۴) پاس شدند؛ بررسی `git diff --check` نیز خطایی نداد.

- نمای روبه‌رو و نیم‌رخ برای اطمینان از پیوستگی تنه با شانه، لگن و لباس هنوز باید در مرورگر دیده شود؛ مرحله از نظر بصری کامل نیست.

### مرحلهٔ ۱۲ — ۲۰۲۶-۱۰-۱۳؛ بازبینی محلی انجام شد

- هدف: در حرکت جلوبازو، اتصال آرنج به بالاترین شعاع ساعد می‌رسید اما حدود ۰٫۰۰۲۸ واحد زیر شعاع ورودی ساعد بود؛ این تلرانس می‌توانست در زاویهٔ خم، درز باریکی بسازد.
- تغییر: پوستهٔ مفصل آرنج از شعاع ۰٫۰۳۲ به ۰٫۰۳۵ افزایش یافت؛ شعاع مؤثر آن اکنون ۰٫۰۳۸۵ است و روی ورودی ساعد با شعاع ۰٫۰۳۸ حدود ۰٫۰۰۰۵ واحد هم‌پوشانی دارد. حلقهٔ تزئینی درون پوسته باقی می‌ماند.
- آزمون: تست مرحلهٔ ۱۲ هم‌پوشانی پوسته با انتهای بازو و ورودی ساعد و فرورفتگی حلقه را بررسی می‌کند؛ ژست جلو بازو در پیش‌نمایش محلی از نمای جانبی بررسی شد و جدایی واضحی در مفصل دیده نشد.
